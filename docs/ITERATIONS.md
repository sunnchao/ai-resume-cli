## 实施决策

- AI 接口使用 Chat Completions API 的 `response_format=json_schema`，不自动回退到其他端点或 mock。自定义 BASE_URL 必须支持 `POST /chat/completions`。
- `extract` / `score` 各使用 2 条虚构 few-shot；样本只示范结构，当前文档始终放在最后一条 user 消息。
- `score --evidence` 选择独立的证据 Schema 与扩展示例。默认 score 的模型请求不要求新字段。
- 所有公开引文在本地匹配原文；mock 匹配固定的虚构文本并标记 `evidence_basis=mock_fixture`。
- 详细证据版本 2 增加 PDF 位置、JD 原文与缺口来源；页码和行号由本地计算，纯字符串输入不编造页码。
- OCR 默认关闭，仅对无文本页执行；layout 为 pypdf 布局模式，不承诺还原任意版面。
- CI 结果以实际运行记录为准；本地 / 容器通过不代表 GitHub Windows 作业已通过。
- 批量只处理显式路径，按顺序执行；逐项失败仍输出报告并退出 7。全局失败不输出报告。
- 评分 AI 返回私有的 JD 三维要求标记。程序据此识别无有效要求的 JD，并对未设门槛的维度设置 100；公开 JSON 沿用原题字段。
- `interview_questions` 在实现中固定为 2-3 条，比原题的示例要求更明确。
- 保存使用同目录临时文件 + 排他硬链接提交，避免检查之后目标被创建时误覆盖；不支持硬链接的文件系统会明确失败。
- 请求超时采用 SDK 的网络超时语义；不能将“每次 30 秒 + 一次重试”描述为进程的硬性 61 秒截止时间。
- 真实模型验证和外部提交不以离线测试代替。无凭据时持续完成其余开发工作，并保留未验证状态。
- 独立二进制用 PyInstaller 在构建机本机打包，不交叉编译；默认目录分发且不打入 OCR extra，避免单文件每次解压导致启动无反馈。产物不提交仓库。Windows 冻结进程启动时把 stdout/stderr 切到 UTF-8；校验按字节解码控制台输出；冻结启动提示使用 ASCII。
- 内部代码按 `domain` / `application` / `adapters` 分层，不预留 Web `interfaces` 包，也不保留已无引用的旧模块垫片。公开入口仍是 `resume_cli.cli:main`。
